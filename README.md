# 过敏原残留追踪 Web 应用

面向**共用设备的小型食品加工车间**的过敏原残留记录与溯源工具。按时间录入每批产品的配方过敏原、依次使用的设备以及设备清洗记录后，系统逐步推演每台设备的残留状态，并给出每批产品的最终过敏原清单与可逐级展开的传播来源链。修改任意记录后立即重新推演。

- 后端：Node.js + Express
- 前端：原生 HTML / CSS / JavaScript（单页，无构建步骤）
- 存储：数据目录下的单个 JSON 文件（无外部数据库依赖）

## 一条命令启动

```bash
docker compose up -d --build
```

启动后访问：

- **本地地址：http://localhost:3000**
- **端口：3000**（宿主机 `3000` → 容器 `3000`，可在 `docker-compose.yml` 的 `ports` 中修改宿主机端口）

依赖安装与数据初始化均在镜像构建 / 容器启动时自动完成，首次启动会在命名卷 `allergen-data` 中自动创建数据文件 `db.json`，无需手动初始化。

停止：`docker compose down`（数据保留在卷中；`docker compose down -v` 会同时删除数据）。

## 本地无 Docker 运行（需要 Node.js ≥ 18）

```bash
npm install
npm start
```

同样访问 http://localhost:3000 。数据默认写入项目下的 `data/db.json`，可用环境变量 `DATA_DIR` 指定其他目录，用 `PORT` 修改端口。

## 使用方式

1. 在左侧「设备」标签页添加共用设备（如搅拌机、油炸锅、传送带）。
2. 「录入批次」：选择时间、填写批次名、勾选配方自带过敏原，按加工顺序添加设备步骤并保存。
3. 「录入清洗」：选择设备，**只勾选本次清洗实际移除的过敏原**（未勾选的残留会保留并继续传播）。
4. 右侧查看：
   - **设备当前残留**：每台设备上现存的过敏原；
   - **时间线**：按时间排列的批次与清洗，可展开每一步的继承/沉积情况；
   - **最终过敏原**：每批标签区分 `配方自带` 与 `交叉获得`；
   - **传播来源链**：对任一交叉获得的过敏原逐级展开，可一直追溯到具体哪个批次的配方。
5. 任何记录都可编辑（✎）、删除（✕），相同时间点的记录可用 ↑/↓ 调整先后；保存后全部结果自动重新推演。也可点击右上角「↻ 重新推演」手动刷新。
6. 首次使用可点击右上角「载入演示数据」查看完整示例场景（花生酱饼干 → 部分清洗 → 无过敏原米饼被交叉污染）。

## 残留推演规则

- **设备状态**：每台设备维护一组"过敏原 → 最新沉积来源"的映射。
- **批次接触设备（按步骤顺序）**：
  1. **继承**：获得该设备接触前的全部残留（每继承一项生成"接触"溯源节点）；
  2. **沉积**：把批次当前携带的全部过敏原（配方自带 + 此前步骤继承）留在该设备上，覆盖该过敏原此前的残留（生成"沉积"溯源节点）。
- **清洗**：仅删除被勾选的过敏原；其余残留原样保留，其来源链会穿过清洗事件（"清洗未移除"节点）。
- **溯源图**：所有节点（配方自带 / 接触继承 / 沉积 / 清洗未移除 / 清洗）通过 `parents` 指向时间更早的节点，构成为有向无环图，前端沿边逐级展开。
- 推演为纯函数：每次保存后从全部记录按时间（`时间` 升序，同时间按录入顺序）重放，因此修改历史记录后结果始终一致。

预置标准十二类过敏原：麸质谷物、甲壳类、鱼类、鸡蛋、花生、大豆、乳及乳制品、坚果、芹菜、芥末、芝麻、二氧化硫及亚硫酸盐；也可在录入时添加自定义过敏原。

## 接口一览（均返回含完整推演结果的状态）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 获取主数据、记录与最新推演结果 |
| GET | `/api/health` | 健康检查 |
| POST | `/api/entries` | 新增批次 / 清洗记录（`kind: batch \| cleaning`） |
| PUT | `/api/entries/:id` | 修改记录（部分字段更新） |
| DELETE | `/api/entries/:id` | 删除记录 |
| POST | `/api/entries/:id/move` | 同时间点上移 / 下移（`{ "dir": "up" }`） |
| POST/DELETE | `/api/equipments`、`/api/equipments/:id` | 设备增删改（被引用的设备不可删除，可改名） |
| POST/DELETE | `/api/allergens`、`/api/allergens/:name` | 过敏原主数据增删 |
| POST | `/api/demo` | 载入演示数据（覆盖当前数据） |

## 目录结构

```
.
├── server.js              # Express 入口与路由
├── src/
│   ├── storage.js         # JSON 文件存储（启动自动初始化、串行原子写入）
│   ├── simulator.js       # 残留推演与溯源图（纯函数）
│   └── demo.js            # 演示数据
├── public/                # 原生前端（index.html / styles.css / app.js）
├── data/                  # 运行时生成的数据目录（db.json）
├── Dockerfile
└── docker-compose.yml
```
